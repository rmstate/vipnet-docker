# 3. Маршруты и обратный трафик

## Проверка
После установки ключей и запуска клиента:

```bash
sudo docker exec <ИМЯ_КОНТЕЙНЕРА> vipnetclient info
sudo docker exec <ИМЯ_КОНТЕЙНЕРА> ip -br addr
sudo docker exec <ИМЯ_КОНТЕЙНЕРА> ip route
```

В документации реальные адреса исходного теста заменены диапазонами, зарезервированными для примеров: `198.51.100.117` и `192.0.2.120`. Это заглушки, а не реальные адреса VPN-узлов. Перед выполнением команд подставьте адреса из своей конфигурации.

## Проверка маршрута
```bash
sudo docker exec <ИМЯ_КОНТЕЙНЕРА> ip route get <IP_ТЕСТОВОГО_УЗЛА>
ip route
ip route get <IP_ТЕСТОВОГО_УЗЛА>
```

Замените заполнители реальными значениями, не копируйте угловые скобки буквально. Сравните маршрут внутри контейнера и на хосте: это разные сетевые пространства. До добавления маршрута сохраните исходный вывод `ip route`; не добавляйте маршрут вслепую.

## Исходящий и обратный трафик
Проверьте:
- выходит ли SYN через ожидаемый интерфейс;
- доходит ли пакет до узла назначения;
- отвечает ли удалённый узел SYN-ACK;
- возвращается ли ответ правильным путём;
- не блокируют ли трафик firewall, NAT или отсутствие обратного маршрута.

Для разрешённого теста можно использовать `tcpdump` на хосте и в контейнере. Не публикуйте pcap без проверки.

Если через контейнер должны ходить другие машины, это отдельный сценарий: могут понадобиться корректные маршруты, forwarding, firewall и NAT. Не отключайте firewall целиком и не используйте `--privileged` как универсальное решение.
